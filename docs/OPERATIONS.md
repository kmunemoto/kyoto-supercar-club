# 運用手順

`docs/SYSTEM_REVIEW.md` で「仕組みはあるが、誰がいつ見るかが決まっていない」と指摘した部分の手順書。

## 独自ドメインへの移行チェックリスト

**メールはサイト公開を待たずに先行できます。** ドメイン名さえ決まれば、下の 1〜3 だけで受付控えと運営通知が実際に届くようになります（現在は Resend のサンドボックス差出人のため、アカウント所有者以外には届いていません）。

### メールを先に通す

1. ドメインを取得する
2. Resend にドメインを登録し、DNS に SPF / DKIM（推奨: DMARC）レコードを追加して検証を通す
3. Lovable Cloud Secrets に設定する
   - `NOTIFY_FROM` = 検証済みドメインのアドレス（例: `KYOTO SUPERCAR CLUB <noreply@example.com>`）
   - `NOTIFY_EMAIL` = **カンマ区切りで 2 件以上**。1 件だと片方が見落としたとき誰も気づかない
4. `/admin` の概況を開き、設定警告が消えていることを確認する
5. テスト送信: 公開フォームから 1 件送り、受付控えと運営通知の両方が届くことを確認する

### サイトを移す

6. `VITE_PUBLIC_SITE_URL` を新ドメインに設定する。**未設定のままだと canonical・sitemap・OGP がすべて旧 URL を正典として指し続けます**（ビルド時に警告が出ます）
7. ビルドし、`public/sitemap.xml` と `public/robots.txt` が新ドメインになっていることを確認する
8. 旧 `*.lovable.app` から新ドメインへの 301 リダイレクトが設定できるか Lovable に確認する。**不可なら、蓄積した SEO 評価の一部は諦める判断になります**
9. Google Search Console でアドレス変更を申請する
10. LINE 公式アカウントや名刺など、外部に出している URL を差し替える

## 週次でやること（金曜など、曜日を決める）

1. **`/admin` の概況を開く**
   - 設定警告が出ていないか
   - 「送信できなかった通知」が出ていないか → 出ていたら、該当リードに自分から連絡する
   - 滞留（3 日以上「新規」／14 日以上動きなし）の件数
2. **バックアップを取る**
   - 概況の「すべて書き出す（JSON）」を実行
   - 一覧ごとの CSV には**メモと対応履歴が含まれません**。この JSON が唯一の完全な複製です
   - 書き出したファイルは個人情報そのもの。暗号化した保管先に置く。保管期間も決めておく
3. **LINE の未転記を確認する**（下記）

## LINE 経由の相談を取りこぼさないために

LINE のトーク画面は管理画面から見えません。転記しない限り、その人には対応状況も滞留検知も削除請求への対応も効きません。

- **相談として成立した時点で** `/admin/intake` から登録する（雑談の段階では不要）
- 登録時に「利用目的を案内し同意を得た」を確認する。得ていなければチェックせずに登録し、次の連絡で案内する
- **削除請求が来たら、管理画面の匿名化と LINE のトーク削除をセットで行う**。片方だけでは対応したことにならない
- スプレッドシート等の**第 3 の記録場所を作らない**。真実が増えるほど漏れる

## 個人情報の削除請求

1. お問い合わせフォームから受け付ける（プライバシーポリシーで公開している唯一の経路）
2. 本人確認をする
3. `/admin` の該当詳細ページ →「個人情報を削除する」。氏名・連絡先・自由記述が消え、件数・ステータス・受付日は統計のために残る。実行は対応履歴に記録される
4. LINE 経由の相談なら、トーク履歴も削除する
5. 対応したことを本人に連絡する（ポリシーで「原則 2 週間以内」と公開している）

## 監視

- **本番の JS エラーはどこにも届きません。** `lovable-error-reporting.ts` はエディタプレビュー内でのみ動きます。フォームが表示されない・送信ボタンが効かないといった障害は、利用者からの連絡でしか分かりません
- 最低限、外形監視（無料枠のサービスで足ります）を公開 URL と `/apply/collection` に設定することを推奨します
- 有料集客を始める時点で、エラー監視の導入とステージング環境の要否を改めて判断してください

## 設定が欠けているとどうなるか

`/admin` の概況に警告が出ます。いずれも**黙って機能が止まる**種類のものです。

| 未設定                                          | 止まるもの                                                           |
| ----------------------------------------------- | -------------------------------------------------------------------- |
| `SUPABASE_SERVICE_ROLE_KEY`                     | 通知の送達記録、重複送信の検知                                       |
| `RESEND_API_KEY`                                | 受付控えと新着通知のメール全部                                       |
| `NOTIFY_FROM`                                   | 実質的な配送（サンドボックス差出人はアカウント所有者にしか届かない） |
| `NOTIFY_EMAIL`                                  | 新着通知の宛先                                                       |
| `VITE_PUBLIC_SITE_URL`                          | canonical・sitemap・OGP が旧ドメインを指す（ビルド時に警告）         |
| `VITE_GA_MEASUREMENT_ID` / `VITE_META_PIXEL_ID` | ファネル計測（実装済みのイベントがどこにも届かない）                 |
